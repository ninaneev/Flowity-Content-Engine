# Supabase — slides editáveis de carrossel

Este documento permite que qualquer membro do projeto prepare o banco para guardar os textos editáveis de todos os carrosséis.

## O que esta migration faz

- Cria `public.carousel_slides`, relacionada a `public.posts`.
- Armazena um texto por slide e sua posição.
- Mantém entre 1 e 10 slides por post; a interface deve exigir no mínimo 3 antes de gerar.
- Preenche/atualiza os slides dos posts existentes usando `hook`, `body` e `cta`.
- Cria automaticamente três slides iniciais quando um novo post é inserido.
- Pode ser executada novamente sem duplicar posições.

> Execute no SQL Editor do projeto Supabase correto. Faça backup antes de aplicar em ambientes com dados importantes.

## SQL completo

```sql
begin;

create table if not exists public.carousel_slides (
  id bigint generated by default as identity primary key,
  post_id integer not null references public.posts(id) on delete cascade,
  position integer not null check (position between 1 and 10),
  slide_text text not null check (length(trim(slide_text)) > 0),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint carousel_slides_post_position_unique unique (post_id, position)
);

create index if not exists idx_carousel_slides_post_position
  on public.carousel_slides (post_id, position);

comment on table public.carousel_slides is
  'Texto editável e ordenação dos slides de cada post.';

-- Cria/atualiza os três slides iniciais de um post.
create or replace function public.sync_initial_carousel_slides(p_post_id integer)
returns void
language plpgsql
as $$
declare
  v_post public.posts%rowtype;
begin
  select * into v_post
  from public.posts
  where id = p_post_id;

  if not found then
    return;
  end if;

  insert into public.carousel_slides (post_id, position, slide_text)
  values
    (v_post.id, 1, left(coalesce(nullif(trim(v_post.hook), ''), 'Título do carrossel'), 220)),
    (v_post.id, 2, left(coalesce(nullif(trim(v_post.body), ''), 'Adicione aqui o conteúdo deste slide.'), 220)),
    (v_post.id, 3, left(coalesce(nullif(trim(v_post.cta), ''), 'Qual é a sua opinião?'), 220))
  on conflict (post_id, position)
  do update set
    slide_text = excluded.slide_text,
    updated_at = now();
end;
$$;

-- Backfill de todos os posts já existentes.
do $$
declare
  v_post_id integer;
begin
  for v_post_id in select id from public.posts order by id loop
    perform public.sync_initial_carousel_slides(v_post_id);
  end loop;
end;
$$;

-- Novos posts recebem slides iniciais automaticamente.
create or replace function public.create_initial_carousel_slides_trigger()
returns trigger
language plpgsql
as $$
begin
  perform public.sync_initial_carousel_slides(new.id);
  return new;
end;
$$;

drop trigger if exists trg_posts_create_carousel_slides on public.posts;
create trigger trg_posts_create_carousel_slides
after insert on public.posts
for each row execute function public.create_initial_carousel_slides_trigger();

commit;
```

## Como conferir o resultado

```sql
select
  p.id as post_id,
  p.hook,
  count(s.id) as total_slides,
  string_agg(s.slide_text, E'\\n---\\n' order by s.position) as slides
from public.posts p
left join public.carousel_slides s on s.post_id = p.id
group by p.id, p.hook
order by p.id;
```

Para editar o texto de um slide:

```sql
update public.carousel_slides
set slide_text = 'Novo texto editável', updated_at = now()
where post_id = 4 and position = 2;
```

Para listar os slides que a interface deve carregar:

```sql
select id, post_id, position, slide_text
from public.carousel_slides
where post_id = 4
order by position;
```

## Importante: edição no frontend e segurança

Criar a tabela não conecta automaticamente a tela do carrossel ao banco. A aplicação precisa carregar `carousel_slides` pelo `post_id`, mostrar `slide_text` em campos editáveis e salvar alterações na tabela, mantendo `position` como ordem.

O projeto atual usa uma API de backend (`postsApi.render.carousel`). Prefira expor endpoints autenticados no backend para listar, criar, editar, remover e reordenar slides, validando que o usuário pode editar o post. Não exponha a chave `service_role` no navegador.

Antes de permitir acesso direto pelo cliente Supabase, configure RLS e políticas compatíveis com a autenticação do projeto. Não habilite RLS sem políticas: isso pode bloquear o acesso esperado. Não use uma política aberta de escrita em produção.
